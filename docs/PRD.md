# 產品需求文件 (PRD) - 選課交換系統

## 1. 專案概述

### 背景與動機
每逢大專院校選課期間，學生常面臨選不到理想課程，或是已經選到但想退掉的課程無法有效利用的情境。透過本系統，學生能將手中不需修習的課程，與其他學生需要的課程進行交換，達成資源最大化利用，減少選課壓力與私下交易的風險。

### 目標用戶
大專院校在校學生。

### 核心價值主張
提供一個安全、匿名且高效率的課程交換平台，透過自動智慧媒合與誠信機制，協助學生快速換到理想課程，降低換課溝通成本與被放鳥的風險。

---

## 2. 功能需求

### 2.1 主要功能清單
1. **使用者身份驗證 (SSO)**：必須串接學校電郵 (SSO) 登入，確保交易對象皆為校內真實學生。
2. **課程許願與持有清單**：使用者可條列「現有課程」與「目標課程」，系統自動進行後台配對。
3. **智慧媒合通知**：當系統發現符合條件的交換對象（含二方甚至三方交換）時，立即透過 Email 或 App 推送通知。
4. **即時通訊系統**：提供站內匿名聊天室，供雙方約定在選課系統離峰時段執行「退選/加選」動作。
5. **誠信評價機制**：建立使用者信用分數，記錄成功換課次數，並對惡意放鳥者進行停權處理。
6. **熱門課程看板**：顯示當前平台上最熱門（最多人想要）與最多人釋出的課程排行榜。

### 2.2 使用者故事 (User Stories)
- **使用者身份驗證**：作為一名學生，我希望只能使用學校信箱登入，以便確認跟我換課的對象都是真實校內學生，避免遭到校外人士詐騙。
- **課程許願與持有清單**：作為一名學生，我希望可以新增我已有的課程與我想換到的課程，以便系統能自動幫我尋找合適的交換對象。
- **智慧媒合通知**：作為一名學生，我希望能在系統找到符合條件的交換者時收到即時通知，以便第一時間登入處理換課事宜。
- **即時通訊系統**：作為一名學生，我希望能在平台上匿名與對方進行對話，以便安全地跟對方約好同時「退選和加選」的精確時間。
- **誠信評價機制**：作為一名學生，我希望系統能封鎖或懲罰惡意放鳥的用戶，以便我能安心地進行退選操作，不怕課被別人截走後對方消失。
- **熱門課程看板**：作為一名學生，我希望能看到全校最熱門的課程與釋出榜單，以便了解目前的熱門選課趨勢與機會。

## 3. 非功能需求

### 技術限制
- **後端框架**：Flask (Python)
- **前端模板**：Jinja2 + HTML/CSS/JS
- **資料庫**：SQLite (適用於初期開發與 MVP)

### 效能與安全考量
- **隱私性**：聊天室與使用者配對資料需妥善保護隱私（使用匿名配對機制）。
- **併發處理**：在選課系統剛開跑的尖峰時段，需確保系統能負擔較大的查詢與即時通訊負載。
- **安全性**：SSO 驗證需遵循相關安全規範（OAuth 2.0 等），防止偽造身份。

---

## 4. MVP 範圍 (Minimum Viable Product)

### Must Have (必須擁有，第一階段核心)
- 使用者身份驗證 (支援學校信箱註冊/登入或基礎 SSO)。
- 課程許願與持有清單的 CRUD (新增、讀取、修改、刪除)。
- 基礎雙方配對演算法 (兩人互換)。
- 基礎的站內即時通訊系統 (或簡單安全的留言板機制) 供雙方聯絡。

### Should Have (應該擁有，第二階段重點)
- 進階智慧媒合通知 (配對成功寄發 Email 提醒)。
- 熱門課程看板 (依據資料庫請求次數計算的簡單排行榜)。

### Nice to Have (可以考量加入，未來擴充)
- 更複雜的多方交換 (如 A給B、B給C、C給A 的三方配對)。
- 完整的誠信評價機制與管理員後台封鎖/停權功能。
- APP 推播功能 (Push Notifications)。
